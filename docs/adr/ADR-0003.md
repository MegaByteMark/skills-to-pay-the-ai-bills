# ADR 0003: PO Persona — Requirements-to-Backlog Orchestration with Gap Analysis, Superseding seed-backlog

## Status

Accepted

## Context

The `po` persona orchestrator (issue #63) coordinates requirements-to-backlog orchestration: it resolves the repository platform once, ingests the PRD/FDS, reconciles requirements against the live tracker via stable-ID markers, detects duplicate and incoherent tickets, and spawns clean-context subagents (`create-epic`, `create-user-story`, `create-bug-report`) for ticket creation/amendment and bug lifecycle. Three tensions motivated this ADR:

1. **Functional overlap with `seed-backlog`.** The existing `seed-backlog` skill already owns write-side orchestration: platform resolve-once, PRD/FDS reconcile, create/amend/close classification, parents-before-children sequencing, single approval gate, and a seed report. Issue #63's `po` persona is that same orchestration plus (a) mandatory gap analysis to prevent duplicate and incoherent tickets and (b) bug lifecycle via `create-bug-report`. Splitting both into active orchestrators would create two reconcilers targeting the same tracker with divergent logic. The decision below supersedes `seed-backlog` rather than duplicating it.

2. **The issue's stated hand-off model.** Issue #63 describes PO as a hands-off orchestrator (like `swe`) that spawns subagents for ticket creation/amendment. `seed-backlog` composes leaves in-process; `po` spawns them as clean-context subagents per the persona-orchestration pattern established by `qa` and `devops` (ADR-0001, ADR-0002) — no parent reasoning or conversation history bleeds into a leaf's context.

3. **`create-bug` vs the existing leaf name.** The issue lists `create-bug` as a subagent-spawning skill, but the repository ships the functional equivalent as `create-bug-report` (a leaf that files bug reports as Work Items via `resolve-repository-platform`). There is no `create-bug` skill; inventing one would duplicate `create-bug-report`. The decision resolves to the existing leaf.

## Decision

1. **`po` is the canonical requirements-to-backlog orchestrator.** It bundles `agent-markup`, `design-vocab`, `resolve-repository-platform`, and `interview-me`, and spawns clean-context subagents for the write-side leaves: `create-epic`, `create-user-story`, and `create-bug-report`.
2. **`seed-backlog` is superseded and deprecated.** Its frontmatter and SKILL.md lead with a DEPRECATED notice pointing to `po` (ADR-0003); the folder is retained for installed users. `po` must never route set-level orchestration back to `seed-backlog`.
3. **Gap analysis is mandatory before any write.** Every seed/reconcile run reconciles tracker work items by stable-ID marker (never title) and classifies create/amend/close/consolidate. Duplicate tickets are consolidated to a canonical work item; drift amends; orphaned stories are flagged (epics before stories); deprecated items close rather than delete.
4. **Bug lifecycle is handled by `create-bug-report`.** The issue's `create-bug` is resolved to the existing leaf; no new skill is created.
5. **Persona-orchestration conventions are preserved:** single platform resolution, single approval gate, clean-context subagent spawning, parents-before-children, stable-ID identity, `[Confidence: Level]` on findings, and zero mutation of the developer working tree.

## Consequences

- **Positive:** One canonical write-side orchestrator; gap analysis prevents duplicate and incoherent tickets at the source; bug lifecycle is now in scope; `po` plugs into the persona pattern consistently with `swe`/`qa`/`devops`.
- **Negative:** `seed-backlog` users must migrate to `po`; the seed/reconcile logic lives behind a persona rather than a plain programmable orchestrator, which is the intended shape per issue #63.
- **Implementation Notes:** Encode the decision in the `po` SKILL.md (PHASES 2–4: gap analysis, approval gate, clean-context execution) and its leaf skills. Deprecate `seed-backlog` (frontmatter notice + version bump). Re-wire dependents (`create-epic`, `create-user-story`, `ba`) and README catalog/compose diagram from `seed-backlog` to `po`. Bump `metadata.version` on each changed skill. Revisit if a non-persona programmable write-side orchestrator is ever required again.
