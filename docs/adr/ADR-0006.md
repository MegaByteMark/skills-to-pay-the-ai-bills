# ADR 0006: Architect Persona — System Blueprinting, Technical Design Decomposition, and Downstream Persona Consumption

## Status

Proposed

## Context

The repository defines an SDLC persona pipeline (`ba` → `po` → `swe` → `qa` → `devops`). While `ba` captures product vision and functional requirements, and `po` coordinates the issue backlog and execution-order DAG, system architecture lacked a dedicated persona orchestrator. Architecture activities were distributed across standalone leaf skills (`analyze-a-codebase`, `db-normalisation`, `architectural-decision-register`, `clean-architecture`, `audit-blueprint-implementation`), with no unified flow bridging high-level requirements to engineering execution.

Three specific tensions motivated this ADR:

1. **Macro vs Micro Architecture Scope:** Architectural design spans two distinct altitudes: macro system topology (greenfield system synthesis or brownfield codebase reverse-engineering) and micro technical design (decomposing specific Epics or Stories into Module structures, Interface contracts across Seams, data schema normalisation, and ADRs). Without an orchestrator, agents risk conflating these or producing fragmented, redundant design docs.
2. **Workspace Pollution and Unapproved Writes:** Delegating to leaf skills can lead to unsolicited file creation across the repository. Architectural designs, schema changes, and ADRs must be fully reasoned, synthesised, and reviewed before touching the workspace.
3. **Downstream Persona Consumption Seams:** Downstream personas (`po`, `swe`, `qa`) need explicit integration contracts to ingest architectural artefacts (`system-blueprint.md`, `data-model.md`, `docs/adr/`, enriched FDS contracts) rather than assuming implicit knowledge or re-deriving architecture ad-hoc.

## Decision

1. **Introduce the `architect` Persona Orchestrator (`skills/architect/SKILL.md`).** The persona operates in three distinct modes:
   - **System Mode (`/architect blueprint` or `/architect analyze`):** Synthesises target system blueprints from PRD/FDS for greenfield systems, or delegates to `analyze-a-codebase` (`[Handoff: Clean]`) to reverse-engineer physical structures for brownfield systems.
   - **Design Mode (`/architect design <EPIC-### | STORY-###>`):** Ingests target requirement items from PRD/FDS, defines Module hierarchies, establishes Interface contracts across Seams, drives relational normalisation via `db-normalisation`, and drafts ADRs via `architectural-decision-register`.
   - **Audit Mode (`/architect audit`):** Delegates to `audit-blueprint-implementation` (`[Handoff: Clean]`) to detect structural drift, broken Seams, leaky Interfaces, or untracked Modules.

2. **Unified Architecture Hub (Canonical In-Repo Locations):**
   - Macro system topology: `docs/architecture/system-blueprint.md`
   - Relational data model: `docs/architecture/data-model.md`
   - Architectural decisions: `docs/adr/ADR-XXXX.md`
   - Work-item technical contracts: enriched directly into the Functional Design Specification (`docs/requirements/functional-requirements.md`) with cross-references to relevant ADRs and Module paths.

3. **Zero-Write In-Memory Gate:** When delegating to subagents or running in-session leaf workflows, all proposed blueprints, ERDs, ADRs, and contract modifications are held in-context. Persistence to workspace paths occurs ONLY after explicit developer confirmation in the Plan & Approval Gate.

4. **Downstream Persona Consumption Contracts:**
   - **`po`:** Considers architectural dependencies (Seams, data model prerequisites, ADR constraints) during execution DAG construction (`roadmap.md`).
   - **`swe`:** Ingests active ADRs (`docs/adr/`), `system-blueprint.md`, and `data-model.md` during feature pickup (`PHASE 0`/`PHASE 2`), ensuring layer placement (`clean-architecture`) and Dependency Inversion across Seams (`solid-principles`).
   - **`qa`:** References `system-blueprint.md` Seam test topologies and data isolation models during Delta and Release-gate audit passes.

## Consequences

- **Positive:** Connects requirements (`ba`/`po`) seamlessly to implementation (`swe`); centralises architecture into canonical locations without document sprawl; enforces developer approval before disk mutation; establishes clear architectural consumption rules across `po`, `swe`, and `qa`.
- **Negative:** Adds an orchestrator skill to maintain; requires minor updates to adjacent personas (`po`, `swe`, `qa`) to formalise architecture artefact consumption.
- **Implementation Notes:** Author `skills/architect/SKILL.md` per `skill-authoring`, `agent-markup`, `design-vocab`, and `agent-handoff` rules. Update `skills/po/SKILL.md`, `skills/swe/SKILL.md`, and `skills/qa/SKILL.md` to document architectural artefact ingestion points. Bump metadata versions across updated skills. Register `architect` in `README.md`.
