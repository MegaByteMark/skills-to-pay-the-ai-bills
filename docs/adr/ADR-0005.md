# ADR 0005: Relocate PO Execution-Order Plan to In-Repo Roadmap Artefact

## Status

Proposed

## Context

PO PHASE 2.7 and PHASE 5 currently persist the execution-order plan to the platform's persistent state store, emitting three out-of-tree files per planning cycle: a dated Markdown view, a `…-plan.json` sidecar (canonical machine schema), and a persisted Backlog Health Report. The schema carries `next_pickup`, `schema_version`, and per-item `status` fields that SWE mutates on pickup and closure.

This produced two problems:

1. **Handoff friction.** A colleague inheriting the repository receives zero in-repo signal of attack order. The plan lives out-of-tree under a per-host path (`~/Library/Application Support/po/<project>/plans/…`), so cloning the repo yields nothing. Three dated files sprawl over cycles and a reader must guess which is current.
2. **Misclassification of state.** The plan conflates two concerns under one out-of-tree artefact: (a) sequencing — a human-authored, human-amended, reviewable roadmap derived from the PRD Epic Register and §5 Assumptions & Dependencies; and (b) progress — machine-mutated `next_pickup` and per-item `status` fields. AGENTS.md "State & persistence" governs (b) but was being applied to (a) as well, forcing the whole artefact out-of-tree.

Platform-native roadmap features (GitHub Projects V2 roadmap view, GitLab epic timeline, Bitbucket — none) were considered as an alternative home. They are too fragmented across the three platforms `resolve-repository-platform` supports: Bitbucket has no roadmap feature; GitHub's roadmap is a view over Projects data, not first-class data; only GitLab has a real epic hierarchy. Pushing the roadmap into platform features would silently break the skill's cross-platform contract.

## Decision

1. **Relocate the sequencing artefact in-repo.** PO writes `docs/requirements/roadmap.md` — a single living file, amended in place, alongside the PRD/FDS it synthesises. Not dated snapshots; not a dedicated `docs/roadmap/` directory (YAGNI — one attack-order view per project). Git history provides per-cycle audit; the tracker holds historical ship record.

2. **Tracker is the runtime state machine.** GitHub Issues (or platform equivalent) assignee + status + milestone provide distributed progress state across hosts. `next_pickup` is derivable, not stored: "first unassigned, open item in the lowest-numbered wave whose hard blockers are all closed." Two SWE agents on different hosts coordinate via tracker assignment, not via a local progress file.

3. **Zero out-of-tree state for PO.** Drop the `…-plan.json` sidecar (Markdown is sole source of truth for sequencing), drop the persisted Health Report file (PHASE 5 echoes to chat — a report is a snapshot, not state), drop `next_pickup` and `schema_version` and per-item `status` from the schema. AGENTS.md "State & persistence" is trivially satisfied — PO writes nothing out-of-tree.

4. **Maximal compaction.** The file is agent-loaded reference material (SWE loads it on pickup). Schema: one-line header (`generated:` · `last-amended:` · `derived-from:`), one-line legend, pipe-delimited milestone rows, DAG edges folded into wave items via `->`/`<-`/`~>` tokens. No tables, no prose, no sidecar.

5. **Platform mirrors best-effort, non-blocking.** PO continues to create/amend milestones via `create-milestone` and work items via the create-* leaves. PO does NOT attempt to configure platform-native roadmap views — too fragmented; the in-repo file is the portable contract.

6. **Roadmap ↔ PRD drift detection.** PRD is source of truth for *what* and *priority*; roadmap is source of truth for *when* (waves) and *how* (edges). When they conflict on priority or dependencies, PRD wins and roadmap amends. When PRD is silent on wave placement, roadmap is authoritative. Detected in PHASE 2 alongside existing tracker↔PRD reconciliation; surfaced in PHASE 3 approval gate.

## Consequences

- **Positive:** Single-file in-repo handoff — a colleague (or AI agent) cloning the repo receives the full attack-order context with no out-of-tree path resolution. Three-file sprawl collapses to one. AGENTS.md state-persistence tension eliminated entirely for PO. Tracker's native concurrency primitives replace a fragile local JSON write-back race. Cross-platform portability preserved.
- **Negative:** SWE now reads two sources on pickup — in-repo `roadmap.md` for wave membership + DAG edges, tracker for live status/assignment. This is a real Seam, but the same shape as the existing "PRD says what features exist, tracker says which are done" reconciliation. SWE pickup location changes — a breaking change requiring a major version bump on both PO and SWE. A human hand-editing `roadmap.md` could break the compact structure; mitigated by PO overwriting on next planning-cycle run (manual edits are intentional overrides, not the norm).
- **Implementation Notes:** Edit `skills/po/SKILL.md` PHASE 2.7 steps 4–5 (in-repo write, drop JSON sidecar/`next_pickup`/`schema_version`/per-item status) and PHASE 5 (cut out-of-tree persistence; chat-echo only). Edit `skills/swe/SKILL.md` PHASE 0 (read `docs/requirements/roadmap.md` + tracker) and PHASE 5 closure (tracker assignment/close is the mutation; no JSON write-back). Bump PO 1.2.0 → 2.0.0 and SWE 1.3.0 → 2.0.0 (breaking: output location + downstream Seam change). ADR-0005 supersedes the out-of-tree plan scheme documented in PO PHASE 2.7 step 4. `docs/domain-glossary.json` does not currently exist in the repo; no glossary update required for this change.
