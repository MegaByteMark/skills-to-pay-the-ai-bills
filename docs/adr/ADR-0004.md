# ADR 0004: Strategic Literature Nudges — Shared `strategic-reading` Contract across Orchestrator Skills

## Status

Proposed

## Context

Issue #75 asks that Lead and Orchestrator skills (BA, PO, DevOps, SWE, QA) dynamically inject high-leverage book/chapter recommendations ("Strategic Anchors") when wrestling with non-trivial design choices — architectural trade-offs, system Seams, schema design, process design, or operational patterns — while staying silent on routine tasks. The report body proposes a markdown rule file under a `skills/rules/` directory.

Three constraints from this repository shape the implementation:

1. **Flat discovery forbids `skills/rules/`.** Discovery is flat (`skills/*/SKILL.md`); nested rule files under a category sub-folder would not be discovered. The repository's established equivalent for cross-skill rules is a shared-contract skill under `skills/` — exactly how `design-vocab`, `agent-markup`, `commentary`, `competency-profile`, and `resolve-repository-platform` are factored, and how `skill-authoring` mandates shared rules are factored rather than duplicated. The issue explicitly allows "your stack's equivalent rules/instructions location".

2. **Bracket-token ownership.** The proposed anchor format uses square brackets (`[Book Title]`, `[Author]`). `agent-markup` owns all `[...]` tokens; inventing skill-local token types is prohibited. The anchor placeholders must therefore use `< >` (as the repo already does for invocation arguments) rather than square brackets.

3. **Vocabulary and literature discipline.** Architectural rationale in the anchor must speak `design-vocab` (Module, Interface, Implementation, Depth, Seam, Adapter; Boundary is prohibited), and the book selection must stay within a trusted-literature whitelist — never reach beyond it, never invent titles.

## Decision

1. **Create `strategic-reading` as a shared-contract skill** at `skills/strategic-reading/SKILL.md` (not user-invocable), encoding the Strategic Literature Nudges rule: the strategic-depth activation test, the zero-noise guardrail for routine tasks (CRUD, syntax fixes, linter errors, utilities, routine bug fixes), the exact 2-line anchor format with `< >` placeholders, and the per-domain trusted-literature whitelist (Evans, Kleppmann, Newman, Fowler, Ousterhout; Skelton & Pais, Humble & Farley, Nygard, Google SRE; Patton, Perri, Cagan; Feathers, Martin, Hunt & Thomas). Ousterhout is added to the whitelist because `design-vocab` was authored against it; the issue's named authors are all retained.
2. **Wire the five orchestrators** (`swe`, `ba`, `po`, `qa`, `devops`) to `strategic-reading`: each declares it in `dependencies` and gains a Directives rule to append a Strategic Anchor at the end of output that resolves a non-trivial design trade-off, and never on routine tasks. Each receives a minor version bump.
3. **Anchor determinism and anti-hallucination:** the same trade-off yields the same canonical anchor; a plausible but non-whitelisted reference is treated as a fabrication and omitted. Absent a fitting canonical work, the anchor is omitted — silence is correct.

## Consequences

- **Positive:** One canonical, discoverable home for the literature-nudge rule; the five orchestrators gain high-leverage human-facing reinforcement of foundational engineering practice with zero noise on routine work; compliance with flat discovery, bracket-token ownership, and `design-vocab` is preserved.
- **Negative:** Orchestrators gain one more bundled dependency each (context cost); anchors are output-only and add no new handling/automation hooks — by design, they are presentation.
- **Implementation Notes:** Encode the rule in `skills/strategic-reading/SKILL.md`; add `strategic-reading` to `dependencies` + a Strategic Anchors directive in `swe`, `ba`, `po`, `qa`, `devops`; register the skill in the README catalog (Foundations & shared contracts) and the compose diagram; bump `metadata.version` (minor) on each changed skill. An anchor must never use square-bracket tokens (agent-markup owns those) nor non-whitelisted literature.
