# ADR 0007: Designer Persona — UI/UX Prototyping, Versioned Design Systems, Accessibility Promotion Gate, and Downstream Backlog Integration

## Status

Proposed

## Context

The repository defines an SDLC persona pipeline (`ba` → `architect` → `po` → `swe` → `qa` → `devops`). While `ba` captures product vision and user stories, and `architect` establishes system blueprints and data models, UI/UX interaction design lacked a dedicated persona orchestrator. UI prototyping was either deferred to ad-hoc frontend coding in `swe` or handled without standardized design governance, leading to four distinct tensions:

1. **Unstandardized Prototypes & CSS Drift:** Without a shared, living design system, ad-hoc screen mockups duplicate inline styles, introducing visual inconsistencies and divergence across screens.
2. **Build Tool Overheads & Offline Resilience:** Screen prototypes that depend on complex build chains or external CDNs fail to render reliably via direct filesystem access (`file://`) or under offline/restricted corporate environments.
3. **Accessibility Regressions:** Accessibility considerations (WCAG 2.2 AA/AAA, contrast ratios, keyboard traps, ARIA semantics, Lighthouse accessibility criteria) are frequently addressed late during code review or QA rather than by design.
4. **Disconnected UI Gap Backlog Seeding:** Uncovered edge cases, missing interaction states, and deferred UI enhancements identified during design walkthroughs risk being lost if not systematically fed into the Product Owner (`po`) backlog.

## Decision

1. **Introduce the `designer` Persona Orchestrator (`skills/designer/SKILL.md`) and `prototype-ui` Leaf Skill (`skills/prototype-ui/SKILL.md`).**
   - **`prototype-ui` (Leaf Skill):** Generates standalone, self-contained flat HTML/CSS/JS prototypes on demand for rapid idea exploration (`/prototype-ui <prompt | spec>`).
   - **`designer` (Persona Orchestrator):** Manages end-to-end design governance across three operational modes:
     - **Design / Prototype Mode (`/designer prototype <flow-name>` or `/designer design <EPIC-### | STORY-###>`):** Ingests PRD/FDS requirements, establishes or consumes the versioned design system, scaffolds multi-screen flows into `docs/design/drafts/`, and conducts interactive walkthroughs.
     - **Accessibility Audit Mode (`/designer audit <screen-path>`):** Performs an adversarial accessibility sweep over prototypes or templates.
     - **Review & Promotion Mode (`/designer review <flow-name>`):** Evaluates accessibility gates, obtains developer sign-off, and promotes validated prototypes from `drafts/` to `approved/`.

2. **In-Repo Design Repository (`docs/design/`):**
   - **Versioned Design System (`docs/design/system/vX/`):** Houses design tokens (`tokens.css`), reusable stylesheets (`design-system.css`), a living pattern library (`component-catalog.html`), and bundled offline assets (`assets/icons.svg`). Prototypes link to these relative assets with zero CDN dependencies.
   - **Lifecycle Separation:** In-progress exploratory prototypes live in `docs/design/drafts/`; signed-off, production-ready prototypes live in `docs/design/approved/`.
   - **Design Register (`docs/design/design-register.md`):** Central ledger tracking Design IDs (`DSGN-###`), title, traced requirements (`EPIC-###`, `STORY-###`, `REQ-###`), version, pinned design system iteration, status (`Draft`, `In-Review`, `Approved`, `Deprecated`), and accessibility verification records.

3. **Adversarial Accessibility & Usability Gate:**
   - Adopts the `adversarial-review` MoSCoW extraction-grade finding schema (`| File:Line | Finding | Suggested Fix | Domain | Priority | Scope | Confidence | Remediation Action |`).
   - Evaluates WCAG 2.2 AA/AAA contrast ratios, semantic HTML5 landmarks, full keyboard operability (`:focus-visible`), form labeling, and Lighthouse 100 accessibility criteria.
   - **Hard Gate:** Zero `MUST FIX` findings permitted for promotion to `docs/design/approved/`. Deferred findings (`[Remediation: Defer]`) are surfaced for PO backlog ingestion.

4. **Downstream Persona Contracts:**
   - **`po`:** Ingests design gaps and deferred findings during backlog reconciliation to generate new tracked User Stories.
   - **`swe`:** Ingests approved prototypes (`docs/design/approved/`) during feature pickup to implement production frontend code faithfully against design tokens and validated interaction states.
   - **`FDS`:** Enriched with explicit links to approved prototypes and verified interaction states.

## Consequences

- **Positive:** Enables instant in-browser prototype exploration without build steps; eliminates CSS drift via versioned design systems; establishes accessibility as a prerequisite before development; bridges design gaps directly into PO backlog items.
- **Negative:** Introduces two skills to maintain; requires minor updates to `po` and `swe` personas to document design artifact ingestion.
- **Implementation Notes:** Author `skills/prototype-ui/SKILL.md` and `skills/designer/SKILL.md` per `skill-authoring`, `agent-markup`, `design-vocab`, and `agent-handoff` rules. Update `skills/po/SKILL.md` and `skills/swe/SKILL.md`. Register skills in `README.md`.
